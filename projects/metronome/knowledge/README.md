# Knowledge

How this project works, kept current. These docs belong to no workflow: they must make sense without `jrg/tickets/`.

| Doc | Owns |
| --- | --- |
| [product.md](product.md) | What it is, who it is for, what works today, product decisions and why |
| [architecture.md](architecture.md) | How it works: structure, data flow, file map |
| [technical.md](technical.md) | Stack, dependencies, technical decisions and why |
| [development.md](development.md) | Setup, commands, testing, deploy, troubleshooting |
| [branding.md](branding.md) | Name, domains, brand direction, themes, wordmark, mascot |
| [launch.md](launch.md) | Launch purpose, measurement, SEO, monetization, the reusable launch playbook |
| [history.md](history.md) | What shipped, dated, newest first |
| `plans/<slug>/` | Plan packets in progress |

Add a `<topic>.md` for anything project-specific (brand, launch, a vendor's quirks) and list it here.

**Rules:** one owner per fact — link instead of repeating. Rewrite what is no longer true; do not append. A ticket that changes how something works updates the owning doc in the same change.
